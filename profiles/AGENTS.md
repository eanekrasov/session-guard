# Инструкции для профилей

## Контекст

Эта директория содержит поставляемые профили харнесса: `profile.json`, workflow-схемы,
инструкции runtime-агентов и проверки invariants. Это не исходный код runtime npm-плагина.

Применяй корневой `AGENTS.md` как общие правила, а этот файл — как уточнение для профилей.
Документация профилей находится в `docs/profile-authoring.md`,
`docs/schema-writing-guide.md`, `docs/schema-reference.md` и `docs/schema-examples.md`.

## Что здесь можно менять

- `profile.json` — метаданные профиля, наследование, схемы, агенты, skills и invariants;
- `*.yaml` — workflow-схемы профиля;
- `agents/*.md` или каталог, указанный в `agentsDir` — runtime-инструкции агентов профиля;
- `invariants.ts` — проверки файлов, если профиль их поставляет.

Профили в этом checkout-е (`base`, `android`, `harness`) — только текущий поставляемый
набор примеров и opinionated-конфигураций команды. Не считай этот список исчерпывающим:
в целевом проекте харнесса могут находиться другие профили, принадлежащие другой команде.
Эти правила применяются к любому профилю, расположенному в каталоге профилей, включая
профили из `SESSION_GUARD_PROFILES_DIR`, а не только к каталогам этого checkout-а.

Перед изменением профиля сначала прочитай `docs/profile-authoring.md`. Перед изменением
workflow-схемы дополнительно прочитай `docs/schema-writing-guide.md` и используй
`docs/schema-reference.md` как справочник. Для примеров используй `docs/schema-examples.md`.

## Границы ответственности

- Здесь описывается поведение конкретного профиля, а не внутренняя реализация плагина.
- Не обходи публичный API плагина, добавляя в профиль знания о его внутренних модулях.
- Если изменение требует правки `src/`, `test/`, сборки или публичного API плагина,
  вернись к корневому контексту разработки плагина и прочитай `docs/plugin-architecture.md`.
- Файлы `agents/*.md` являются промптами запускаемых runtime-агентов. Не применяй их
  правила к себе автоматически при редактировании профиля.
- Если изменяешь файл внутри `agents/`, считай его runtime-промптом, а не новым источником
  общих правил для разработчика. Сохраняй его роль, границы, инструменты и формат результата.
- Для runtime-промпта используй инструкции корневого `AGENTS.md` и этого файла; не ожидай,
  что каждый профиль будет содержать собственный `AGENTS.md`.

## Проверка изменений

- Сохраняй совместимость `profile.json`, схем и связанных fixtures.
- Проверяй, что имена схем, `extends`, списки агентов и пути соответствуют существующим
  типам и контрактам; не создавай ad hoc-структуры, если подходящий контракт уже существует.
- Для `profile.json` выполни проверку metadata/schema и проверь загрузку профиля.
- Для `*.yaml` выполни проверки schema compiler/loader и отдельно проверь happy path и failure
  path, если они затронуты изменением.
- Для `agents/*.md` проверь синхронизацию агентов или соответствующий профильный smoke-сценарий.
- Для `invariants.ts` выполни проверки invariants.
- Для изменений, затрагивающих runtime, публичный контракт или поставочные артефакты, выполни
  `mise run check` и `mise run build`; для host-интеграции дополнительно выполни `mise run smoke`.
- Зафиксируй фактически выполненные проверки и их результат. Не объявляй работу завершённой,
  если обязательная проверка не запускалась или завершилась ошибкой.
