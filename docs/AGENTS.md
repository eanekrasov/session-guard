# Инструкции для документации

## Контекст

Эта директория содержит документацию для разработки npm-плагина, разработки харнесса
и профилей, а также обычной работы пользователя под управлением харнесса.

Корневой `AGENTS.md` содержит общие правила агента и карту контекстов. Этот файл уточняет
только порядок работы с документацией и не заменяет корневые инструкции.

## Маршрутизация документов

Перед чтением документа определи задачу и выбери подходящий контекст:

- **Разработка плагина:** `plugin-architecture.md`, `usage.md`, `configuration.md`.
- **Разработка харнесса или профиля:** `architecture-overview.md`,
  `profile-authoring.md`, `schema-writing-guide.md`, `schema-reference.md`,
  `schema-examples.md`, `configuration.md`.
- **Работа пользователя:** `user-guide.md`, `feature-status.md`, `usage.md`,
  `troubleshooting.md`; `architecture-overview.md` и `faq.md` загружаются по необходимости.

`architecture-overview.md` используется в двух последних контекстах, но с разными целями:
автор профиля изучает жизненный цикл и границы интеграции, а пользователь — причины
блокировок и состояние workflow.

## Владение документами

- `plugin-architecture.md` — внутренняя архитектура и границы разработки плагина.
- `usage.md` — установка, сборка и проверка подключения.
- `configuration.md` — переменные окружения и настройка подключённого плагина.
- `profile-authoring.md` — создание и изменение профилей.
- `schema-writing-guide.md` — написание workflow-схем.
- `schema-reference.md` — справочник полей workflow-схем.
- `schema-examples.md` — примеры workflow-схем.
- `user-guide.md` — повседневная работа пользователя.
- `feature-status.md` — подтверждённые возможности и ограничения.
- `architecture-overview.md` — жизненный цикл харнесса и границы ответственности.
- `troubleshooting.md` — диагностика установки и работы.
- `faq.md` — часто задаваемые вопросы по использованию.

Не применяй `plugin-architecture.md` и `CONTRIBUTING.md` как инструкции пользователя
или автора профиля. Не применяй `user-guide.md` как правила разработки runtime плагина.
Файлы `profiles/**/agents/*.md` являются runtime-инструкциями профилей, а не общей
документацией и не правилами разработки плагина.

## Метаданные документов

При создании или существенном переписывании документа добавляй в начало блок:

```md
> **Контекст:** разработка плагина / разработка профиля / работа пользователя.
>
> **Загружать, когда:** краткое описание задачи.
>
> **Не использовать для:** соседние контексты, которые этот документ не регулирует.
>
> **Связанные документы:** ссылки на дополнительные материалы.
```

Не переписывай один и тот же материал в нескольких документах. Выбери один источник
истины и добавь ссылки из остальных документов.

## Проверка изменений

- Перед изменением документа проверь `git diff HEAD -- <file>`.
- После изменения проверь diff повторно и запусти `git diff --check`.
- Не объявляй документацию готовой, если ссылки ведут на несуществующие файлы.
- Утверждения о поведении OpenCode, плагина или харнесса проверяй по исходному коду
  или официальной документации, а не только по соседнему документу.
